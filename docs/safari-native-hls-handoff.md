# Safari playback of interlaced restreams: handoff (session ended 2026-09-30)

Channels: `MNX.in`, `DisneyInternationalHD.in`, `ColorsCineplexBollywood.in`
(`http://<raw IP>:8000/play/<id>/index.m3u8`, Astra restream, 576i/1080i H.264 field-coded, MP2 audio).

## Status

| Browser | State |
|---|---|
| Chrome | Plays (verified by the owner and by pixel sampling). |
| Safari (macOS) | **Sound, no picture.** Not fixed. Every "no picture" run in real Safari shows `getVideoPlaybackQuality()` frames == dropped. |

Everything else in the original brief is shipped and verified: player resilience, proxy sniffing,
raw-IP/port-8000 origins over `cloudflare:sockets`, Surprise me, engine ladder, `Loading…` stall fix.

## What was proven (real Safari 26.6.2, objective numbers from the lab in `docs/safari-lab/`)

- hls.js (MSE) fails on these streams in every configuration (`mediaSourceRequiresReset`); mpegts.js the same.
- WebCodecs: Safari's `VideoDecoder` says "Decoder failure" on MNX (also with `prefer-software`, AVCC + description).
  The identical code decodes a normal progressive stream (600 frames, 1280x720), so the demux/AVCC path is sound.
- Native `<video src>` on the **live** playlist: first frame after 8-16 s, then every frame dropped.
- Native on **local static copies** of the same bytes can play. Results depend on the playlist and on where playback starts:
  - complete segments: VOD from segment 1 played, from segments 0 and 2 did not;
  - **segments re-cut on I-pictures with nothing dropped play, VOD and live-style** (ffmpeg's `-c copy` HLS, and our `repackSegment`);
  - trimming the pre-I pictures away (dropping them) did not play.
- Local test data is only valid when every segment is complete: the origin's newest segment is still being written
  and it deletes old ones ~3 s after listing; 188-byte bodies are its "gone" stub.

## What shipped for Safari

- `functions/api/_lib/tsTrim.ts` `repackSegment(cur, next)`: output = `cur` from its first I-picture + the head of `next` up to
  its first I-picture. Loss-free (unit test: every field and audio unit exactly once across a chain).
- `functions/api/proxy.ts` `?repack=1`: playlist rewritten with `seg=1&next=<following segment>`, newest live segment held back;
  segment request returns the repacked bytes (Range/HEAD answered from the repacked bytes as of the last commit).
  Bodies capped at 4 MB, upstream fetch failure or non-TS falls back to the ordinary path, segments cached 40 s in `caches.default`.
- Client: only streams already routed to Safari's native player (`prefersNativeHls`, persisted 30 days) request `repack=1`.
  `localStorage.sl_no_repack = '1'` turns it off. No client-side processing was added.

Verified on production: repacked MNX segments start on an I-picture with SPS/PPS, `X-Segment-Repacked: with-next`,
three consecutive outputs contiguous (192/128/128 fields, no gap).
**Still no picture in real Safari through the real app**, and the lab's production-URL variant (`#41`) shows frames == dropped.

## Open hypotheses (in order)

1. The last fix (Range/HEAD served from repacked bytes, commit after `fe83450`) has **not been tested in Safari yet**.
   Before it, any request with a `Range` header got the *unrepacked* original. Test first.
2. Delivery timing: local instant delivery plays, real delivery (about 2.5 s TTFB per repacked segment because it fetches two
   origin segments) does not. A throttled local simulation (`live-slow*.m3u8` in the lab) never started at all, which was
   never explained (possibly the lab server ignoring Range). Redo it with Range support.
3. `#EXTINF` says 2.88 s but repacked segments are 2.56-3.84 s. Try true durations.
4. Live playlist mechanics in native HLS (start position, playlist reload): try EVENT/VOD-window presentation on the real stream.
5. If none work: server-side transcode relay (ffmpeg, progressive H.264/AAC, Safari only), or the honest
   "video cannot be shown in Safari" message on "audio plays, zero frames shown".

## Lab (`docs/safari-lab/`)

`server.mjs` (port 8780, collects a 1 Hz event log from Safari to `log.ndjson`) + `index.html` (arrow keys cycle variants;
`#N` opens variant N; `?run=` tags a run). `tools/nals.py` lists NAL types per PES; `tools/cap4.mjs` captures complete origin
segments and repacks them. Copy `node_modules/hls.js/dist/hls.min.js` to `hls.js` and `node_modules/mpegts.js/dist/mpegts.js`
next to `index.html`; the `trim/` fixtures are regenerated by `cap4.mjs`. **Close every lab tab between runs and quit Safari
(Cmd-Q) before a serious measurement**: many open videos exhaust decoder sessions and make results erratic.
